# CFR Protocol v1.0.0-rc.1

**Release type:** GitHub pre-release  
**Status:** Release candidate for integration and security review; not a final 1.0.0 stability promise.  
**Crates.io:** This GitHub pre-release does **not** publish any package to crates.io. The maintainer will publish the crates separately after the RC review period.

## Overview

CFR Protocol v1.0.0-rc.1 is the first release candidate of the Causal Frontier Ratchet implementation. It packages the current protocol, codec-aware media protection, bounded state codecs, and crash-safe durable conference boundary for integration testing and independent review.

> This release candidate is intentionally conservative: it fixes the public facade package name and documents the compatibility contract, but does not claim that the public API, wire format, or persistence format are irrevocably frozen before final `v1.0.0`.

## Highlights

| Area | RC capability |
|---|---|
| Public facade | The user-facing Cargo package and Rust import namespace are now `cfr_protocol`. |
| Group protocol | Leaderless causal-frontier group key agreement with signed operations, prekey rotation, repair, eviction evidence, and key-confirmation beacons. |
| Media | Codec-aware authenticated protection for H.264, AV1, VP8, Opus, and generic framed media, with replay protection and selective-forwarder inspection. |
| Durable state | Versioned participant/media codecs plus a full-state snapshot and WAL boundary for restart, idempotency, durable outbox, and sender/replay continuity. |
| Recovery | Fail-closed recovery of snapshot/WAL state, bounded incomplete-tail truncation, checksum and marker validation, explicit unknown-version rejection, and resource limits. |
| Quality controls | Strict formatting, all-feature Clippy, workspace tests, no-`std` build checks, documentation warnings, fuzz targets, coverage, CodeQL, and dependency policy automation. |

## Public package and namespace

The facade package is named **`cfr_protocol`**. Once the maintainer publishes the RC packages to crates.io, downstream users should declare and import it as follows:

```toml
[dependencies]
cfr_protocol = "1.0.0-rc.1"
```

```rust
use cfr_protocol::{Codec, Conference, Policy, Recipient};

let (mut alice, _bootstrap) = Conference::create(Policy::leaderless(2))?;
let bob = cfr_protocol::Joining::new(Policy::leaderless(2))?;
let outbound = alice.invite(&bob.key_package())?;
let welcome = outbound
    .iter()
    .find(|message| message.to == Recipient::Peer(bob.identity()))
    .expect("invitation creates one welcome for the joining peer");
let (mut bob, _) = bob.accept(&welcome.payload)?;

let frame = [0, 0, 0, 1, 0x65, 0xDE, 0xAD];
let sealed = alice.protect(Codec::H264, &frame, true)?;
let (_from, plaintext) = bob.open(&sealed)?;
assert_eq!(plaintext, frame);
```

The internal implementation crates intentionally retain their existing names: `cfr-crypto`, `cfr-core`, and `cfr-media`. Cryptographic domain-separation labels beginning with `cfr/` are protocol constants and are not package aliases.

## Protocol and persistence contract

The wire representation and durable-state formats use explicit version fields. The current RC defines protocol-facing state schema and store-envelope version `1`. Unknown versions are rejected explicitly; the implementation does not guess legacy formats or synthesize migrations.

The durable `PersistentConference` boundary commits a full candidate state to a versioned WAL before replacing the in-memory state. It owns a bounded inbound idempotency window and durable outbox, and it persists media sender/replay state under the same transaction boundary. Snapshot creation, WAL reset, and recovery use synced temporary files, atomic rename, directory sync, checksums, and commit markers.

| Boundary | v1.0.0-rc.1 behavior |
|---|---|
| Public Rust API | Treat as RC API: feedback-driven breaking changes may still occur before final 1.0.0. |
| Network messages | Existing codec/parser strictness is part of the RC interoperability target; reject unknown or non-canonical encodings. |
| Persistent state | No implicit migration. Back up state before upgrading an RC deployment and test restore with the target binary. |
| Package name | `cfr_protocol` is the supported external facade name for this RC. |
| Internal crates | Do not treat `cfr-core`, `cfr-crypto`, or `cfr-media` as a stable standalone integration contract during the RC period. |

## Security and operational boundaries

CFR is a local protocol library, not a transport or identity-authentication service. Applications provide authenticated out-of-band key-package delivery, transport delivery, media framing, and persistent-state placement. Durable state includes key material in plaintext; Unix owner-only filesystem modes mitigate accidental local disclosure but do not encrypt the state directory.

The RC retains the documented non-goals: it does not claim protection against endpoint compromise, malicious dependencies, compromised kernels or root, metadata analysis, denial of service, or application-level identity mistakes. Read the architecture, security, and integration documentation before deployment.

## RC validation

The tag is created only after the current main commit passes the full local release gate and the repository workflows. Validation includes formatting, warnings-as-errors Clippy, all-feature workspace tests, release build, no-`std` checks, Rustdoc warnings, fuzz-manifest validation, dependency policy, coverage, and CodeQL.

The RC review should focus on independent protocol review, multi-process/interoperability integration, crash/recovery drills on realistic state directories, and public API ergonomics. Report an issue with a minimal reproducer, platform/toolchain, feature set, and whether the failure affects protocol, persistence, or media handling.

## Publishing boundary

This GitHub prerelease creates an annotated source tag and a reviewable changelog only. It deliberately does **not** invoke `cargo publish`, upload registry credentials, or make a crates.io availability claim. The repository retains a separately manually dispatched, confirmation-protected crates.io workflow for the maintainer's later decision.
